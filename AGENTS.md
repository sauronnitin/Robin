## Learned User Preferences

- Prefer hybrid LLM routing: Gemini Flash for thinking agents (Fit/Tailor/Cover/Humanizer), Groq 8B for tool/mechanical agents. Never Gemini Pro.
- Prefer the agent to use existing workspace Google Auth or Drive credentials rather than asking the user to hunt for keys manually.
- For the agents pipeline live preview, keep the UI compact and mostly visual with no scrolling; favor a node-based dashboard layout.
- Whenever a feature or backend capability is added (new agent, task, tool, route, setting), also ship the matching dashboard GUI in the same change: regenerate `dashboard/pipeline-data.js` via `python dashboard/_gen_pipeline_data.py`, wire canvas edges/cards, expose controls or status in the UI, and verify the card/control is visible after refresh. Backend-only drops without a GUI surface are incomplete.
- Before overwriting `dashboard/` with a major UX iteration, archive the current folder into `dashboard-archive/vNN-short-slug/` (use `python dashboard-archive/snapshot.py`) and append a `VERSIONS.md` entry. See `dashboard-archive/save-iteration.md`.
- At the start of any JobHunter session (and before claiming a pipeline/dashboard task is done): read `dashboard/errors/latest.json` (or `GET http://localhost:5959/api/errors/latest` if the server is up). If `ok: false` and `open.length > 0`, fix those issues first. Never ask the user to paste Activity errors when that file exists. During live runs, keep watching that bus: treat a user-initiated Stop as intentional (thinking or screen recording); on automatic failure or stop, diagnose and fix without waiting for the user.
- In the dashboard model picker: list provider models with connection status (active / inactive / disconnected); do not unilaterally prune models the user might choose; remove discontinued models only; show Load only when disconnected.
- When Drive is configured, save pipeline/agent outputs into the JobHunter Google Drive project folder, not only under local project paths.
- Prefer USA-first job search (then Canada/EMEA), product/UX/UI design roles across all boards, and last-24-hour postings as high priority; defer Oceania, Dubai, Singapore, South Korea, Brazil, and Japan.
- Keep LinkedIn applications in a separate disconnected canvas loop (not the main Scout→Log chain); support both Easy Apply and external Apply; flag JD AI/bot-check jobs for user edit before applying.
- For canvas sections: Figma-like group/ungroup (Ctrl+Shift+S / Ctrl+Shift+U); sections movable and user-resizable; host Sim/Start/Stop/Pause on a floating card docked to the section right edge (not header chrome); keep Done/Stage/Flags/Tokens/Elapsed top-right; allow canvas pan over cards inside sections; dragging cards out of a section keeps card data but drops edges; multi-selected cards move together.
- Canvas bottom-left chat must stay project-aware (planning, pipeline, canvas/run/errors) and action-capable (execute supported dashboard controls, not only describe them). Preview cards should show understandable agent/browser activity; confirm with the user and show approx token cost before any LLM-backed preview narrate.

## Learned Workspace Facts

- JobHunter AI is a local CrewAI job-application pipeline; phased build spec lives in `.planning/BUILD_PLAN.md` and session position in `.planning/STATE.md`.
- Canonical CrewAI Studio export source is `jobhunter_ai_v1_crewai-project - export/` in the project root (the `reference/studio-export/` path from the plan was never populated as a literal folder).
- Hybrid LLM routing: Fit/Tailor/Cover/Humanizer on `gemini/gemini-2.5-flash`; Scout/Compile/Apply/Logger on `groq/llama-3.1-8b-instant`; screener is deterministic Python with Groq 8B fallback. Requires `GEMINI_API_KEY` + `google-genai`.
- Google auth is OAuth2 with a Desktop app client (`google-oauth-client.json` plus cached `google-oauth-token.json`), not a service account; personal Google accounts give service accounts zero Drive storage quota so create-file tools fail. Credential downloads may land in `Google Auth/` before project-root paths.
- Browser automation uses Playwright with a persistent context under `browser-session/`; `DRY_RUN=True` is the default until real applications are explicitly enabled.
- The agents live-preview UI lives under `dashboard/` and is served locally via `python dashboard/server.py` (default http://localhost:5959).
- Prior dashboard UI iterations are archived under `dashboard-archive/` (self-contained per version). Demo with `python dashboard-archive/serve.py <vNN-slug>`. Interview notes: `dashboard-archive/VERSIONS.md`.
- Durable error bus: `dashboard/errors/latest.json` (current opens/healed/resolved) + `dashboard/errors/history.jsonl`. Sim auto-heals safe graph issues; live failures (`awaiting_retry`, run failed) mirror into the same file. APIs: `GET/POST /api/errors/latest|report|resolve`.
- Canvas graph drives execution: `buildRunPlan()` in `dashboard/app.js` compiles in-loop nodes (reachable from Trigger, or roots if none); `buildRunPlan({ sectionId })` scopes runs to a section. Figma-like `kind: "section"` frames persist in localStorage (`sections` on `jh-canvas-graph-v1`) with movable/resizable bounds; section run controls live on a right-edge floating card. Sim and live Start POST the plan; `src/jobhunter_ai/graph_crew.py` builds the sequential Crew. Trigger schedules via `POST /api/schedule` while `dashboard/server.py` is up (not OS Task Scheduler).
- Pipeline canvas cards come from `dashboard/pipeline-data.js` (generated by `dashboard/_gen_pipeline_data.py` from agents.yaml/tasks.yaml), not from static HTML. Main loop uses `AGENTS`/`EDGES`; LinkedIn loop uses `LI_AGENTS`/`LI_EDGES`/`LI_SECTION` as a separate disconnected chain (main Apply skips linkedin.com URLs). New agents must be added to `_gen_pipeline_data.py` ORDER and regenerated so they appear as cards.
- Live run telemetry flows through `src/jobhunter_ai/events_bus.py` (task/llm/tool events) into the dashboard Activity, Tokens, traces, and card Running/Thinking states. Playwright UI actions can surface via `src/jobhunter_ai/browser_preview.py` into observational Preview cards.
- Canvas chat is the bottom-left `#chatDock` via `POST /api/chat` (`src/jobhunter_ai/canvas_chat.py` on Gemini Flash): rich project context each turn, structured `{reply, actions}`, server executes retry/abort/resolve_errors, client applies sim/start/stop/pause and related canvas mutations.
